description: "Understand Heyrafiki's current publication boundary and open-infrastructure principles."
---

Heyrafiki intends to make useful parts of its Mental Healthcare Infrastructure inspectable, extensible and portable. Open source must strengthen safety and interoperability, not expose private data or publish unfinished contracts.

## Current stage

The production application repository is not public. The documentation repository is private while the initial architecture, contribution workflow and release boundaries are reviewed.

<Note>
  A public repository, licence or stable extension interface has not been announced. These docs will change when that status changes.
</Note>

## What openness should provide

- Readable contracts for APIs, Webhooks, Packages and MCP tools
- Portable data and provider boundaries
- Reviewable security and reliability decisions
- Clear contribution and governance rules
- Self-hosting guidance where the operating model can protect clinical and financial data

## What remains protected

Open source does not make clinical records, identity data, private Conversations, credentials or financial evidence public. Access control, Consent, audit evidence and data minimization apply regardless of deployment model.

## Publication gates

Before a component becomes public, Heyrafiki must define:

1. its licence and maintainers;
2. supported interfaces and versioning policy;
3. security reporting and release process;
4. data and deployment boundaries;
5. tests, examples and operational guidance.

Read [versioning and compatibility](/reference/versioning) for the contract that public interfaces will follow.
